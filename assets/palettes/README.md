# Palette assets

Pre-generated palettes consumed by the runtime cycler ([`bin/themes-cycle.sh`](../../bin/themes-cycle.sh)).
Each palette is a directory holding a ready-to-use `kitty.conf` and `starship.toml`, so the cycler never has to run `pastel` on the shell-startup hot path.

## Layout

```
assets/
├── palettes/            # the cyclable set (one directory per palette)
│   ├── NeonPink/
│   │   ├── kitty.conf   # kitty colour include
│   │   └── starship.toml# full starship config (palette selector + block)
│   └── NordFrost/
│       ├── kitty.conf
│       └── starship.toml
└── fallback/            # safety profile used when no palette is usable
    ├── kitty.conf
    └── starship.toml
```

The cycler picks one directory under `palettes/` at random per new terminal.
`fallback/` sits outside that pool and is only used when `palettes/` is empty or a selection fails; it is anchored on the fixed fallback colours `#0a0512` / `#100e23` / `#ff00aa`.

## Regenerating with tuiGen

Palettes are generated by the `tuiGen` flow in the `design-flows` repository.
Point its output at this directory and it will write `<Name>/kitty/` and `<Name>/starship/` trees; move the two files into a `palettes/<Name>/` directory here.

```bash
# From the design-flows checkout
./flows/tuiGen/src/tuiGen --target kitty,starship --preset nord \
    -o /path/to/themes/assets/palettes
```

The sample `starship.toml` files carry a minimal demonstration prompt.
Replace the `format`/modules with your own, but keep the `palette = "<name>"` selector and the `[palettes.<name>]` block so the prompt tracks the active palette.

## Adding a palette by hand

Create `palettes/<Name>/kitty.conf` (a kitty colour include) and `palettes/<Name>/starship.toml` (a complete starship config selecting a `[palettes.<name>]` block).
No other registration is needed — the cycler discovers directories under `palettes/` automatically.
